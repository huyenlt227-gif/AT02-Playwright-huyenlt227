10.2test.step: Business-Level Reporting

EN Raw Playwright reports show technical actions ("click", "fill"). This framework wraps flows in test.step(...) so the report shows business steps — exactly like your manual test case steps:

VI Report Playwright thô chỉ hiện thao tác kỹ thuật ("click", "fill"). Framework này bọc các luồng trong test.step(...) để report hiện bước nghiệp vụ — giống hệt các bước trong test case thủ công của bạn:

TypeScript 
await test.step('Step 4 - Payment: place the order', async () => {
  await paymentPage.expectPaymentStep();
  await paymentPage.enterAdditionalInfo(paymentData.additionalInfo);
  if (paymentData.agreeToTerms) {
    await paymentPage.agreeToTerms();
  }
  await paymentPage.completeOrder();
});

await test.step('Step 5 - Confirmation: capture and verify the order code', async () => {
  await confirmationPage.expectConfirmation();
  const orderCode = await confirmationPage.expectOrderCodeNotEmpty();
  log.info(`Order code received: ${orderCode}`);
});
i
When a test fails at "Step 4 - Payment", you instantly know where the flow broke — no need to decode raw actions. This is the report speaking your language.

10.3The Log File

EN The log fixture (TC-06) writes a per-test text log. Open utils/logger.ts: every log.info(...) in a test lands both in the terminal and in logs/<date>/<test-title>-<timestamp>.log.

VI Fixture log (TC-06) ghi log text riêng cho từng test. Mở utils/logger.ts: mọi log.info(...) trong test đều xuất hiện cả ở terminal lẫn trong logs/<date>/<test-title>-<timestamp>.log.

10.4Reading the HTML Report

EN npm run report opens the interactive report. From a Manual Tester's perspective:

VI npm run report mở report tương tác. Theo góc nhìn Manual Tester:

  • Overview: tổng số test, pass/fail/skip, thời lượng — như bảng tổng kết test run.
  • Test detail: click một test → danh sách business steps, mỗi step có thời gian riêng.
  • Errors: thông điệp fail + assertion message bạn tự viết (TC-04).
  • Trace viewer: mở trace của test fail để xem từng action, network và console.
Exercise · Bài tập
  1. Cố tình làm một test fail: đổi một expected message trong data/login/login-data.json thành chuỗi sai.
  2. Chạy npm run test:login — test fail.
  3. Mở test-results/ và liệt kê các artifact được sinh ra (screenshot, video, trace).
  4. Mở file log của test fail trong logs/<date>/ — tìm dòng lỗi.
  5. Hoàn tác dữ liệu, chạy lại cho xanh.
