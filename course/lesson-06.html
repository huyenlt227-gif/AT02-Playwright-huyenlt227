6.1The Problem Fixtures Solve

EN Without fixtures, every test that needs a page object writes const loginPage = new LoginPage(page) — boilerplate repeated in every file. Fixtures let Playwright create and inject these objects for you, declared once.

VI Không có fixture, test nào cần page object cũng phải viết const loginPage = new LoginPage(page) — boilerplate lặp lại trong mọi file. Fixture cho phép Playwright tạo và tiêm các object này cho bạn, khai báo một lần.

TypeScript 
// ❌ Without fixtures
test('login', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.open();
});

// ✅ With fixtures — Playwright injects a ready page object
test('login', async ({ loginPage }) => {
  await loginPage.open();
});

6.2base.fixture.ts: the Injection Point

EN Open fixtures/base.fixture.ts. It extends Playwright's base test and registers every page object plus the log logger:

VI Mở fixtures/base.fixture.ts. Nó mở rộng test gốc của Playwright và đăng ký mọi page object cùng logger log:

TypeScript 
export type AppFixtures = {
  loginPage: LoginPage;
  productPage: ProductPage;
  cartPage: CartPage;
  confirmationPage: ConfirmationPage;
  log: TestLogger;
};

export const test = base.extend<AppFixtures>({
  loginPage: async ({ page }, use) => {
    await use(new LoginPage(page));
  },
  productPage: async ({ page }, use) => {
    await use(new ProductPage(page));
  },
  // ... every other page object ...

  log: async ({}, use, testInfo) => {
    const logger = new TestLogger(testInfo.title);
    await use(logger);
    logger.info('TEST FINISHED');
  },
});

export { expect };

async ({ page }, use) => { await use(new LoginPage(page)); }Setup: tạo page object → giao cho test qua use()
testInfoMetadata của test (title…) — dùng để đặt tên file log
export { expect }Test import expect từ fixture để dùng chung

6.3Setup & Teardown Lifecycle

EN Code before use() runs before the test (setup); code after use() runs after the test (teardown). The log fixture uses this: it creates the logger, hands it to the test, then writes TEST FINISHED when the test ends.

VI Code trước use() chạy trước test (setup); code sau use() chạy sau test (teardown). Fixture log tận dụng điều này: tạo logger, giao cho test, rồi ghi TEST FINISHED khi test kết thúc.

TypeScript 
log: async ({}, use, testInfo) => {
  const logger = new TestLogger(testInfo.title);  // setup
  await use(logger);                              // test runs here
  logger.info('TEST FINISHED');                   // teardown
},

6.4Composing Fixtures: authenticated-user

EN Fixtures can build on other fixtures. fixtures/authenticated-user.fixture.ts extends base.fixture and adds userSession — a check that the saved login session is still valid:

VI Fixture có thể xây trên fixture khác. fixtures/authenticated-user.fixture.ts mở rộng base.fixture và thêm userSession — kiểm tra session đã lưu còn hợp lệ:

TypeScript 
export const test = base.extend<AuthenticatedUserFixtures>({
  userSession: async ({ page }, use) => {
    await page.goto(`${Env.USER_BASE_URL}/`, { waitUntil: 'domcontentloaded' });
    const bouncedToLogin = page.url().includes('/users/login');
    expect(
      bouncedToLogin,
      'User session is not valid. Re-run the setup and check the .env credentials.',
    ).toBe(false);
    await use(true);
  },
});

EN Any test that declares userSession in its arguments automatically runs this check first. If the session expired, the test fails early with a clear message instead of failing mysteriously at step 5.

VI Test nào khai báo userSession trong tham số sẽ tự động chạy kiểm tra này trước. Nếu session hết hạn, test fail sớm với thông điệp rõ ràng thay vì fail bí ẩn ở bước 5.

Exercise · Bài tập
  1. Liệt kê toàn bộ fixture trong AppFixtures và AuthenticatedUserFixtures.
  2. Thêm fixture mới today: string trả về ngày hiện tại (YYYY-MM-DD), rồi dùng nó trong một test bất kỳ để log.info(today).
  3. Chạy test đó và mở file log trong logs/<date>/ — xác nhận có dòng INFO.
