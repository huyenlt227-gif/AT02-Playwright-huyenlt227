11.1A Systematic Method

EN Debugging is not guessing. Follow this order — each step narrows the cause:

VI Debug không phải đoán mò. Làm theo thứ tự này — mỗi bước thu hẹp nguyên nhân:

#Step · BướcWhere · Làm ở đâu
1Đọc thông điệp lỗi + step failTerminal / HTML report
2Xem assertion message (bạn tự viết)Report → Errors
3Đọc file log của testlogs/<date>/<test>.log
4Xem screenshot tại thời điểm failtest-results/<test>/
5Mở trace, xem action cuối cùng trước khi failTrace viewer
6Chạy lại test (đôi khi lỗi là tạm thời)Terminal
i
Reproduce first. A bug you cannot reproduce is a rumor. Re-run the single test before changing anything: npx playwright test tests/user/login/login.spec.ts --project=login.

11.2The Four Classic Failures in This Project

1 · "Invalid login credentials" on every login

EN The demo site resets its data periodically. When it does, the documented accounts stop working. Verify the credentials manually in a browser; if the account is gone, register a new one and update .env, then re-run the setup.

VI Site demo reset dữ liệu định kỳ. Khi reset, tài khoản mẫu ngừng hoạt động. Kiểm tra tài khoản thủ công trên trình duyệt; nếu mất, đăng ký tài khoản mới, cập nhật .env, rồi chạy lại setup.

2 · HTTP 419 (CSRF token mismatch) when adding to cart

EN The shared demo occasionally rejects POST requests. This is a site-side issue — retry the test. Not a framework defect.

VI Demo dùng chung thỉnh thoảng từ chối request POST. Đây là lỗi phía site — chạy lại test. Không phải lỗi framework.

3 · Popup intercepted my click

EN The demo popup / cookie banner can appear late and swallow clicks. The framework handles this in BasePage.closeAnnoyingPopups() and LoginPage.login(). If you see a "element intercepted" error, check that your new page object calls closeAnnoyingPopups() after goto().

VI Popup demo / banner cookie có thể xuất hiện muộn và nuốt cú click. Framework xử lý trong BasePage.closeAnnoyingPopups() và LoginPage.login(). Nếu gặp lỗi "element intercepted", kiểm tra page object mới của bạn có gọi closeAnnoyingPopups() sau goto() không.

4 · Browser executable not found

EN Version mismatch between Playwright and its browsers. Fix: npx playwright install.

VI Lệch phiên bản giữa Playwright và trình duyệt. Cách xử lý: npx playwright install.

11.3Using the Trace Viewer

EN The trace is the most powerful evidence: it records every action, network request and console message. Open a trace from the HTML report (test detail → "Trace") or directly:

VI Trace là bằng chứng mạnh nhất: nó ghi lại mọi action, request mạng và console message. Mở trace từ HTML report (chi tiết test → "Trace") hoặc trực tiếp:

bash 
npx playwright show-trace test-results/<test>/trace.zip

EN In the trace: step through actions on the left, watch the page snapshot on the right, and inspect the network tab for failed requests (e.g. a 419).

VI Trong trace: tua từng action bên trái, xem snapshot trang bên phải, và kiểm tra tab network cho request lỗi (ví dụ 419).

11.4Debugging with AI — the Right Way

EN The README defines the AI "Debug" role. Give the AI context, not mystery:

VI README định nghĩa vai trò AI "Debug". Hãy đưa AI bối cảnh, không phải câu đố:

text 
My test failed at "Step 4 - Payment: place the order".
Error: expect(locator).toBeVisible() timed out...
The screenshot shows the payment page with no "Place Order" button.
The log shows: "Order code received:" never printed.
What is the likely cause and what should I check?
!
You stay responsible. AI suggests causes; you verify by re-running the test. Never mark a bug "fixed" on AI's word alone.

  4. Viết một prompt debug cho AI theo mẫu 11.4, chạy thử, rồi tự xác nhận lại bằng cách chạy lại test.
