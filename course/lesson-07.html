7.1The Problem: Logging In Every Test

EN Most tests need a logged-in user. Logging in at the start of every test is slow and repetitive — and the demo site even rate-limits logins. The solution: log in once, save the session, reuse it.

VI Hầu hết test cần người dùng đã đăng nhập. Đăng nhập đầu mỗi test vừa chậm vừa lặp lại — site demo còn giới hạn số lần login. Giải pháp: đăng nhập một lần, lưu session, tái sử dụng.

bash 
setup/user-auth.setup.ts  →  storage/user-state.json
setup/admin-auth.setup.ts →  storage/admin-state.json

7.2The Setup Project

EN setup/user-auth.setup.ts is a special test that logs in and snapshots the browser's session (cookies + storage) to a JSON file:

VI setup/user-auth.setup.ts là một test đặc biệt: đăng nhập rồi chụp lại session của trình duyệt (cookie + storage) vào một file JSON:

TypeScript 
import { test as setup } from '@playwright/test';
import { Env } from '../utils/env';
import { LoginPage } from '../pages/user/LoginPage';

setup('authenticate as customer', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.open();
  await loginPage.loginSuccess(Env.CUSTOMER_EMAIL, Env.CUSTOMER_PASSWORD);
  await page.context().storageState({ path: 'storage/user-state.json' });
});

EN The magic line is page.context().storageState({ path: ... }) — it exports the session so other tests can import it.

VI Dòng quan trọng là page.context().storageState({ path: ... }) — nó xuất session ra để test khác import lại.

7.3Wiring It Up in playwright.config.ts

EN The config defines projects. Projects can depend on the setup projects and apply the saved session:

VI Config định nghĩa các project. Project có thể phụ thuộc vào setup project và áp dụng session đã lưu:

TypeScript 
const userStorageState = { storageState: 'storage/user-state.json' };

projects: [
  { name: 'setup-user', testMatch: /setup\/user-auth\.setup\.ts/ },
  {
    name: 'chromium',
    testMatch: /tests\/user\/(?!login).*\.spec\.ts|tests\/e2e\/.*\.spec\.ts/,
    use: { ...desktopChrome, ...userStorageState },
    dependencies: ['setup-user'],
  },
]
ProjectstorageStateWhy · Vì sao
setup-user / setup-admin—Sinh session, lưu ra file

chromiumuser-state.jsonMọi test user khác + e2e: tái sử dụng session

i
Dependencies chain: if setup-user fails (bad credentials), the chromium project is skipped, not failed randomly. Fix the credentials, re-run the setup, and the suite recovers.

7.4Validating the Session

EN A saved session can expire. That is why authenticated-user.fixture.ts adds the userSession fixture (TC-06): before the test, it visits the home page and asserts the site does not bounce back to login.

VI Session đã lưu có thể hết hạn. Đó là lý do authenticated-user.fixture.ts thêm fixture userSession (TC-06): trước test, nó mở trang chủ và assert site không bị hất về trang login.

!
Security: storage/ contains real session cookies — it is git-ignored. Never commit it, never share it. Same for .env.

7.5When the Session Breaks

EN Symptoms: tests fail with "User session is not valid" or suddenly bounce to the login page. Fix:

VI Triệu chứng: test fail với "User session is not valid" hoặc bị hất về trang login. Cách xử lý:

bash 
# 1. verify the credentials still work in a browser
# 2. re-run the setup projects
npx playwright test --project=setup-user --project=setup-admin
Exercise · Bài tập
  1. Chạy riêng setup project và xác nhận storage/user-state.json được tạo.
  2. Mở file đó — quan sát cấu trúc (cookie, origins). Đừng commit file này.
  3. Xóa file storage/user-state.json, chạy npm run test:cart — ghi lại điều gì xảy ra (project bị skip?).
  4. Chạy lại setup rồi chạy lại test — suite hồi phục chưa?
