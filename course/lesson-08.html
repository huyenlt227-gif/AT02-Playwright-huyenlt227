8.1Why Data Lives Outside the Code

EN Test data changes more often than test logic. A product slug, an address, an error message — these are data, not behavior. Keeping them in data/*.json means a BA or QC can update the data without touching code, and the same data can be reused across tests.

VI Test data thay đổi thường xuyên hơn logic test. Slug sản phẩm, địa chỉ, thông báo lỗi — đó là data, không phải hành vi. Để chúng trong data/*.json giúp BA/QC cập nhật data mà không đụng code, và cùng bộ data dùng lại được cho nhiều test.

JSON 
// data/cart/cart-data.json
{
  "productA": { "slug": "gio-qua-tet-orzpq", "name": "Giỏ quà Tết orZpq" },
  "productB": { "slug": "gio-qua-tet-htosw", "name": "Giỏ quà Tết HTOsw" }
}

8.2Reading Data with Types

EN JsonHelper.readData<T>() reads a file from data/ and gives it a TypeScript type, so typos are caught at compile time:

VI JsonHelper.readData<T>() đọc file trong data/ và gán kiểu TypeScript, nên lỗi gõ sai bị bắt ngay lúc biên dịch:

TypeScript 
const cartData = JsonHelper.readData<{
  productA: { slug: string; name: string };
  productB: { slug: string; name: string };
}>('cart/cart-data.json');

await productPage.open(cartData.productA.slug);
await cartPage.expectProductInCart(cartData.productA.name);

// utils/env.ts — typed access to .env
export class Env {
  static get CUSTOMER_EMAIL(): string {
    return process.env.CUSTOMER_EMAIL ?? '';
  }
  static get USER_BASE_URL(): string {
    return process.env.USER_BASE_URL ?? 'https://cms.anhtester.com';
  }
}
✕
Hardcoding is a review finding. When AI reviews this framework (README §AI support → Review), it flags hardcoded credentials, URLs and data. If you see "customer@example.com" inside a test file — that is a defect.

8.4Writing Results: JSON + Excel

EN Tests don't only read data — they produce it. The product-info test captures what the site displays and saves it two ways. Open tests/user/product/get-product-information.spec.ts:

VI Test không chỉ đọc data — còn tạo ra data. Test thông tin sản phẩm capture những gì site hiển thị và lưu theo hai cách. Mở tests/user/product/get-product-information.spec.ts:

TypeScript 
await test.step('Save the information to a JSON file', async () => {
  const suffix = testInfo.project.name === 'chromium' ? '' : `-${testInfo.project.name}`;
  const jsonPath = productData.output.jsonPath.replace('.json', `${suffix}.json`);
  JsonHelper.write(jsonPath, product);
  expect(fs.existsSync(path.resolve(process.cwd(), jsonPath))).toBe(true);
});

await test.step('Save the information to an Excel file', async () => {
  const excelPath = productData.output.excelPath.replace('.xlsx', `${suffix}.xlsx`);
  const savedPath = await ExcelHelper.writeProductDetails(excelPath, product);
  expect(fs.existsSync(savedPath)).toBe(true);
});

EN The output lands in output/products/ as both product-details.json and product-details.xlsx — handy when the business wants the data in a spreadsheet.

VI Kết quả nằm trong output/products/ dưới dạng product-details.json và product-details.xlsx — tiện khi business cần dữ liệu dạng bảng tính.

i
Cross-browser suffix: when Firefox/WebKit also run, the file gets a -firefox / -webkit suffix so parallel browsers don't overwrite each other's output (more in TC-09).
